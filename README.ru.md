# Claude Desktop Guard

Отдельное приложение для **Claude Desktop, вкладки Code**, на Windows и macOS.

Вы выбираете локальный HTTP-прокси, проверяете выход, явно закрепляете IP и страну. Guard запускает Claude через свой барьер и закрывает туннели при смене выхода, узла Mihomo или ошибке проверки.

Это контроль маршрута. Доказанной защиты от бана нет: серверные правила аккаунта остаются у Anthropic.

## Запуск

1. [Скачайте сборку](https://github.com/w1zardz/claude-desktop-guard/releases) под Windows x64, Apple Silicon или Intel Mac. Сборки без подписи и нотариализации; применяются обычные правила допуска приложений вашей ОС.
2. Полностью завершите Claude Desktop. Минимальная версия — `1.44121.1`; контракт локальной конфигурации изучен на `2.19675.0`.
3. Запустите ваш VPN/Clash/Mihomo с локальным HTTP-входом. Введите его адрес в Guard. SOCKS, чужие адреса и пароли в URL не принимаются.
4. Нажмите **Проверить выход**, затем **Закрепить этот IP**. Скрытого выбора адреса, страны или узла нет.
5. При необходимости задайте контроллер Mihomo, группу и конкретный конечный узел. Настройте правила самого Mihomo; Guard проверяет выбранную группу, но не подменяет ваши правила.
6. Нажмите **Запустить Claude через Guard**. Работайте в локальной Code-сессии.

При ошибке проверки новые и открытые туннели закрываются. Барьер сам не открывается обратно. Закрытие окна сворачивает Guard в трей; остановка оставляет Claude привязанным к закрытому прокси. Для возврата прежнего маршрута завершите Claude и нажмите **Восстановить настройки**.

## Что важно

- Прямого резервного соединения у барьера нет. HTTPS остаётся зашифрованным: промпты не переписываются, выдуманная история не добавляется.
- Проверки идут через ipify и ipinfo каждые 10 секунд. Их сбой или ограничение запросов тоже блокирует доступ.
- Наблюдение IP не доказывает маршрут каждого домена при раздельных правилах прокси.
- Windows требует отдельного VPN kill switch/firewall для блокировки всех прямых соединений.
- Строгий режим macOS ограничивает сеть запущенного дерева процессов. Команды без поддержки HTTP-прокси, локальные previews/MCP/browser bridge могут перестать работать.
- Обновления, вход во внешнем браузере, Cloud, SSH, WSL и отдельные системные службы требуют своих сетевых настроек.
- Проектные настройки `.claude/settings*.json` могут переопределить пользовательский прокси. Ранее запущенные фоновые процессы не входят в новую песочницу. Guard не переписывает проектные файлы.
- Часовой пояс показывается для аудита. Браузерное расширение `notme` не внедряется в Desktop; полной маскировки отпечатка здесь нет.
- При восстановлении сохраняются обнаруженные чужие изменения. Обнаруженный конфликт прекращает автоматическое восстановление; журнал остаётся локально. Закройте другие редакторы настроек: их записи Guard не блокирует. Резервная копия может содержать ваши секреты.
